## Decision

A deterministic selector for **Liminal Facility / `BackroomsFlow` on Offense** is technically designable by reusing the repository-proven **selector-only one-postfix architecture** already validated by AGDIAG1 and DRDIAG1.

The reusable architecture is:

> Apply exactly one postfix to `LethalLevelLoader.DungeonManager.GetValidExtendedDungeonFlows(ExtendedLevel, bool)`, ordered after the accepted S1.42AB normalizer at `Priority.Last`; on the validated real Offense server-selection path, verify that exactly one already-returned Liminal Facility wrapper exists with `DungeonName == "Liminal Facility"`, exact `DungeonFlow.name == "BackroomsFlow"`, and final normalized rarity `100`; only then reduce that fresh returned list to the same existing wrapper as a singleton.

This remains a **selection-only diagnostic technique**. It must not manufacture eligibility, rewrite rarity, register a dungeon, change generation parameters, patch traversal, alter entrance topology, mutate NavMesh, hook RNG, replace the selection RPC, or change enemy/scrap/BCMER behavior.

The existing AGDIAG1 or DRDIAG1 binaries, identities and source trees must **not** be retargeted or repurposed. Any later Liminal implementation requires a new separately versioned diagnostic identity and source tree.

This preflight authorizes **no source implementation, compile, build, publication, Gale import, activation or runtime execution**.

The Liminal target satisfies the same prerequisite shape as the already completed Drains cycle:

- exact Offense classification: `VIABLE_EQUAL_100`;
- availability mechanism: `DIRECT_LLL_UNIVERSAL_TAG_OVERRIDE`;
- canonical LLL dungeon name: `Liminal Facility`;

- no owner-hard-block bypass is required;
- record 245 preserves no Liminal-specific generation, CullFactory, route/NavMesh, topology or owner-safety warning.

The architecture itself has now been validated twice end-to-end:

1. AGDIAG1 proved that one post-normalizer selection postfix can retain the exact already-viable rarity-100 wrapper and still allow normal downstream DunGen generation, CullFactory materialization and PathfindingLib entrance relationship logging to complete.
2. DRDIAG1 reused that architecture for a different `DIRECT_LLL_UNIVERSAL_TAG_OVERRIDE` target, Drains, and again produced a complete diagnostic-generated generation/materialization PASS without a second observer patch.
3. Both completed diagnostics stayed `DIAGNOSTIC ONLY / NEVER ACCEPT`, and neither result established natural target-selection frequency.

Therefore no new source investigation is required to justify the interception **surface** for Liminal Facility. Any later implementation still requires its own exact target literals, new identity, pure fail-closed tests, static validator, Patch Safety Review and dedicated source/static workflow.
