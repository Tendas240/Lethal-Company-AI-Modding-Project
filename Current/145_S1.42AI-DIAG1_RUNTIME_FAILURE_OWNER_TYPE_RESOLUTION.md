## Root cause

`Patches/S142AIDiag1Isolation/PackageOwnerGuards.cs` currently hardcodes:

```csharp
ResolveRequiredType("LethalMin.PikminType")
```

for the generic argument needed by `LethalMin.Onion.WithdrawPikminFromOnion(...)`.

The pre-build static validator `AnalysisTools/validate_s142ai_diag1_static.py` validates that owner method using the decompiled short parameter spelling `List<PikminType>`, but it does not prove the CLR full name of the generic argument that the runtime resolver later asks `AccessTools.TypeByName(...)` to resolve. This allowed a green static gate despite the runtime reflection contract being invalid.

## Required repair contract

The successor diagnostic must not replace the bad string with another guessed namespace string.

The minimal repair is:

1. resolve the exact declared `LethalMin.Onion.WithdrawPikminFromOnion` contract from runtime metadata;
2. require exactly one declared instance method with return type `IEnumerator`, three parameters, parameter 0 equal to `List<T>`, parameter 1 equal to `int[]`, and parameter 2 equal to the exact resolved `LethalMin.Leader`;
3. derive `T` directly from the exact `List<T>` parameter metadata;
4. fail closed unless `T` is a coherent LethalMin type with the expected `PikminType` identity;
5. use that exact `Type` object for the owner-method lookup;
6. harden `AnalysisTools/validate_s142ai_diag1_static.py` so the materialized LethalMin DLL proves the corresponding CLR generic-argument contract rather than only the short decompiled spelling;
7. add a regression assertion preventing the known-bad hardcoded `LethalMin.PikminType` resolver from returning unnoticed.

Only after the source repair and strengthened static gate pass repository-native validation should a successor diagnostic profile be built and offered for runtime testing.
