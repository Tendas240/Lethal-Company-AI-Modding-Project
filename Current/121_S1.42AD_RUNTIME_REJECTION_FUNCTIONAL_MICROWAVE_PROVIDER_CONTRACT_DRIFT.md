## Why this is a rejection

S1.42AD intentionally required an exact fail-closed provider contract. The runtime contract did not match that frozen assumption, so refusing mutation was the safe behavior.

The build is rejected because its target behavior was not applied, not because the fail-closed mechanism malfunctioned.

Do **not** weaken the contract by simply deleting the Interior-curve check or blindly scaling both dictionaries. Runtime evidence proves that Interior curves exist, but this run does not by itself establish which Moon/Interior curve table(s) DawnLib selects under `PrioritiseMoons = true`, nor does it prove the exact Moon-curve key set because S1.42AD returned before that validation step.
