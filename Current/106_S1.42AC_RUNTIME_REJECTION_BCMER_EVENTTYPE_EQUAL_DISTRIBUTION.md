## Primary acceptance gate — FAIL

S1.42AC attempted to make all eight BCMER EventTypes equally likely by setting the eight `[_EventType Weights]` scales in `Difficulty_Settings.cfg` to the identical constant curve:

`12.5, 0.0, 12.5, 12.5`

`Use custom weights? = false` remained preserved.

The runtime gate required all eight BCMER lines for the same roll context:

`Set eventType weight for <type> to <value>`

and required the resulting values to be identical.

The fresh runtime log contains five repeated roll contexts. In every observed context the effective values were:

| EventType | Runtime weight |
| --- | ---: |
| Insane | 6843 |
| VeryBad | 506 |
| Bad | 355 |
| Neutral | 1368 |
| Good | 1244 |
| VeryGood | 2737 |
| Rare | 27375 |
| Remove | 883 |

These values are strongly unequal. Therefore the target fixed normalized distribution of `8 × 12.5%` was **not achieved** under the acceptance interpretation used at the time.

This was acceptance-blocking under the then-current gate and was sufficient to reject S1.42AC. The later exact-source analysis in `Current/109...` supersedes the interpretation that equal EventType probability requires equal per-event log values; it does not silently change the formal historical rejection status.

## What the runtime evidence proves about the config assumption

The accepted S1.42AB runtime already emitted unequal final BCMER EventType weights, but with a different set of values. S1.42AC changed those final values, so the eight configured EventType scales do influence the BCMER calculation.

However, setting all eight scales to the same constant does **not** make the logged per-event weights equal. The later BCMER 1.71.0 source inspection in `Current/109...` established that BCMER divides aggregate EventType mass across the enabled events of that type, so unequal logged per-event values are expected under equal aggregate EventType scales.

### Do-not-repeat rule

Do **not** build inverse compensation merely to make all eight logged per-event values equal. If the EventType scope is continued, evaluate the existing S1.42AC artifact under the corrected aggregate static EventType-probability model from `Current/109...`.
