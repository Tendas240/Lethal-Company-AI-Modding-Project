The next critical test concerns LethalMin enemy grab/bite interactions with invincible Pikmin.

Random full-roster spawning makes targeted validation unnecessarily slow and can hide the exact interaction behind unrelated enemies/events.

- Puffer / Spore Lizard (internal reference: Puffer)

## Preferred implementation

Prefer a project-local **test-only runtime spawn isolation guard/overlay** rather than rewriting every normal spawn-owner config.

Reason:
- several enemies have native owners;
- LethalLevelLoader and BCMER have separate responsibilities;
- custom mods can use their own spawn routes;
- mass-editing many configs creates restoration risk.

The diagnostic layer should:
1. allow Crawler/Thumper and Puffer on indoor spawn routes;
2. allow Baboon Hawk on outdoor routes;
3. reject other enemy spawns for this diagnostic build;
4. also block non-allowlisted event/native-mod bypass spawns if they occur;
5. add explicit runtime logging when it rejects or permits a spawn;
6. be clearly marked as diagnostic/test-only.

Do not use this isolation component in the later normal gameplay build.

## S1.42D validation goals

Primary:
- reproduce a generic enemy grab/bite against an invincible Pikmin;
- confirm the new generic state repair prevents the repeated `Leader is null when following` loop.

Specific:
- Thumper and Pikmin do not interact in either direction;
- Puffer smoke/attack does not affect Pikmin;
- Baboon Hawk may interact normally enough to exercise the generic grab/bite path, but an invincible Pikmin must recover into a valid state instead of getting stuck.

Secondary orthogonal checks in the same build:
- Jetpack target ~140 seconds;
- Jetpack does not explode from sustained/high-speed boost use;
- Functional Microwave editing gate true and volume 0.7.

## After S1.42D

The first post-isolation gameplay candidate must remove the diagnostic spawn isolation and restore the full enemy roster/configuration from the S1.42C restore point while retaining only fixes/tuning that passed validation.
