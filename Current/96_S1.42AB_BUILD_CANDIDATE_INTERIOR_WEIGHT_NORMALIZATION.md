## Why S1.42AA was rejected

Fresh S1.42AA runtime evidence from `RuntimeEvidence/S1.42AA/20260904T153744Z/` proved that changing `Inject Dynamic Matching Weights = true -> false` did not equalize LethalLevelLoader's effective dungeon selection weights.

On Offense the runtime pool still contained unequal values including LiminalHouse `300`, Sub Systems `275`, Abandoned Foundry `250`, Shatteredrooms `75`, Lead Factory `70`, Spelunkers Caverns (Random) `50`, Crimson Keep `35`, Gray Apartments `25`, DeepcoreMines `25`, and `20`-weight interiors.

LLL's matching architecture retains the highest matching rarity. Therefore generic `Vanilla:100,Custom:100` entries cannot lower a stronger author/planet/mod match such as `300` to `100`.

S1.42AA is not accepted. S1.42AB is built directly from accepted S1.42Z and does not inherit AA's failed config switch.

## Exact S1.42AB architecture

Patch target:

`LethalLevelLoader.DungeonManager.GetValidExtendedDungeonFlows(ExtendedLevel, bool)`

S1.42AB installs a Harmony **Postfix only**. LethalLevelLoader first performs its complete native matching and exclusion logic. The project-local Postfix then receives the already-filtered viable result list and changes only positive `rarity` values to exactly `100`.

Resulting rule:

- not returned by LLL -> remains unavailable;
- returned with positive rarity -> becomes `100`;
- no flow is appended;
- no flow is removed;
- no flow is re-registered or deduplicated;
- no LLL matching/config list is rewritten;
- Enemy, Scrap and MapObject rarity systems are untouched.

This also implements the permanent future-interior rule automatically: newly installed interiors receive effective rarity `100` whenever LLL considers them viable, without requiring a new per-interior project override.

## Important runtime-log interpretation

LethalLevelLoader writes its built-in `Viable ExtendedDungeonFlows` report **inside the original method before the Postfix returns**. Therefore that built-in line may still display the old pre-normalization author weights such as `300`, `275`, `75`, etc.

The authoritative S1.42AB evidence is the project-local marker emitted after normalization:

`[InteriorWeightNormalization] Final effective viable pool for <moon>: ...`

Every positive flow listed in that line must be `(100)`.

A second marker summarizes how many entries were changed and the original rarity range.
