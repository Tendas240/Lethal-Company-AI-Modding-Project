Therefore adding a diagnostic merely to observe Art Gallery generation would duplicate already-proven logging capability and unnecessarily mutate the experiment.

## Minimum proof contract

A future Art Gallery acquisition can close the current **basic actual-generation/materialization proof gap** only if all mandatory clauses below are satisfied in one coherent ordinary Offense generation.

### A. Ordinary selection identity

Mandatory:

1. moon identity is **Offense**;
2. no Art-Gallery force-selector or target-specific diagnostic is active;
3. normal LLL availability still exposes Art Gallery as viable/effective `100`;
4. the selected interior is attributable to **Art Gallery**, and the post-generation exact flow identity is attributable to **`MuseumInteriorFlow`**.

The strongest repository-native identity chain is:

- LLL/day-history or equivalent normal selection marker identifying **Art Gallery**;
- later CullFactory exact flow preparation identifying **`MuseumInteriorFlow`**.

The accepted pre-existing viable-pool/DawnLib-resolution evidence from the current topic remains supporting context, not a substitute for observing the actual selected run.

### B. Completed generation

Mandatory after the Art Gallery selection:

1. normal generation reaches a completed floor boundary, including `Players finished generating the new floor`;
2. the normal generation segment contains an exact-flow materialization marker such as CullFactory `Preparing tile information for MuseumInteriorFlow`;
3. no persistent DunGen generation-failure/retry condition prevents completion.

A stronger completion chain may additionally contain:

- `Dungeon has finished generating on this client after multiple frames`;
- CullFactory `Generation has completed with seed ...`.

Those strengthen provenance but are not independently required when the mandatory completion + exact-flow materialization chain is already unambiguous.

### C. Generated entrance/materialization evidence

Mandatory:

- PathfindingLib records the ordinary generated exterior/interior entrance relationships for the concrete Art Gallery layout, at the same proof standard used by C1's generated-only rows.

For ordinary Offense, the expected minimum is **four logical entrance connections** matching the established C1 proof model.

A LethalMin summary such as `Found 8 entrances` or equivalent paired-entry reporting is useful corroboration but is not required when the PathfindingLib relationship set is complete and unambiguous.

### D. Negative-boundary handling

The following do **not** erase positive generation proof by themselves:

- isolated RuntimeNavMeshBuilder warnings;
- isolated route/reachability warnings;
- lack of player entry;
- lack of a Pikmin route-use marker.

Those belong to separate routing/NavMesh/traversal proof dimensions unless a concrete target-correlated severe failure prevents the generated layout from functioning.

Conversely, a selection marker alone, viable-pool presence alone, or a generated-flow asset resolution alone is **not** sufficient actual-generation proof.

## Stochastic-selection boundary

This preflight establishes observability, not deterministic acquisition.

Art Gallery currently participates in a large equal-weight viable Offense pool. Failure to roll Art Gallery in an ordinary run is therefore **no evidence against the flow**.

A read-only diagnostic would not solve stochastic selection. A force-selection diagnostic would materially change the experiment and is **not authorized** by this preflight.

If a future ordinary selected Art Gallery run unexpectedly lacks one of the required normal observability markers, that run must be classified as incomplete evidence. It must not automatically trigger diagnostic implementation; a new separately bounded observability-gap decision would be required first.
