# 40 — S1.42K superseded; S1.42L bidirectional attack-rule correction

**Date:** 2026-09-03
**Game:** Lethal Company V81

## User decision after S1.42K build, before S1.42K runtime test

S1.42K was built successfully but was not runtime-tested.

The user clarified that Pikmin should be able to be thrown onto and attack/latch both:
- Thumper/Crawler;
- Baboon Hawk.

Therefore S1.42K is superseded as an untested intermediate candidate.

## Revised permanent interaction rules

### Thumper/Crawler -> Pikmin

Keep the existing project-local protection:
- block Crawler/Thumper-owned `PikminAI.GrabPikmin`;
- no leader removal;
- no grabbed death timer;
- no leader-null loop.

The Thumper may still visibly snap/bite toward Pikmin, but Pikmin must not receive the broken LethalMin grabbed-state effect.

### Pikmin -> Thumper/Crawler

Allow normal LethalMin attack/latch behavior.

Do not keep `Crawler` in LethalMin `[Pikmin Behavior] Attack Blacklist`.

### Baboon Hawk -> Pikmin

Keep the S1.42J protection unchanged:
- exact `LethalMin.BaboonBirdPikminEnemy` adapter disabled after `BaboonBirdAI.Start`;
- exact declared `BitePikmin` blocked;
- common `PikminAI.GrabPikmin` Baboon-Hawk failsafe retained.

Baboon Hawks must not target/chase/bite/grab/hold Pikmin.

### Pikmin -> Baboon Hawk

Allow normal LethalMin attack/latch behavior.

Do not keep `Baboon hawk` in LethalMin `[Pikmin Behavior] Attack Blacklist`.

## Why removing Baboon hawk from the blacklist should not restore the old bug

S1.42J runtime showed LethalMin registration:
`Registered Baboon hawk As Pikmin Enemy, Added (1) latch triggers`

The project-local guard then disables only the exact `LethalMin.BaboonBirdPikminEnemy` behaviour component one frame after `BaboonBirdAI.Start`.

The latch trigger is a separate LethalMin registration artifact and is not removed by the project-local adapter-disable loop.

Therefore the intended architecture is asymmetric:
- incoming Pikmin attacks/latches remain available;
- Baboon-Hawk-owned Pikmin targeting/bite/grab paths remain disabled.

Runtime validation is still required.

The next candidate removes both again.

Note:
the historical legacy juijui LethalMin config contains only `Docile Locust Bees,Manticoil`, but that old profile is not the canonical modern baseline and used a different historical LethalMin/mod environment. Do not treat every additional modern S1.40B/S1.41 default/retained entry as a newly introduced current-project change without separate evidence.

Build S1.42L from S1.42K with only one additional config delta:
remove `Baboon hawk` from the LethalMin Attack Blacklist.

Expected final blacklist:

## S1.42L runtime gate

Validate in one run:
1. throw Pikmin onto a Thumper/Crawler -> Pikmin must latch/attack;
2. Thumper/Crawler -> Pikmin GrabPikmin still blocked;
3. throw Pikmin onto a Baboon Hawk -> Pikmin must latch/attack;
4. Baboon Hawk must still ignore Pikmin completely from its own AI side;
5. no Baboon bite/grab/hold loop;
6. no `Leader is null when following`.

If this passes, the isolated enemy interaction gate is complete.
