## Corrected root cause

Exact LethalMinNightly 1.1.108 decompile shows that `BaboonBirdPikminEnemy` inherits `PikminEnemy`.

The inherited `PikminEnemy.Update()` contains the native enemy-death lifecycle:

1. detect `enemyScript.isEnemyDead`;
2. call `RemoveAndDisableTriggers()`;
3. each latch trigger calls `RemoveAllPikmin(3)`;
4. the adapter marks itself dead and disables itself only after native cleanup.

This is the missing first half of the lifecycle that earlier S1.42Q/R analysis did not account for.

The project compatibility plugin's Baboon-Hawk protection did this after `BaboonBirdAI.Start`:

`behaviour.enabled = false`

for the exact `LethalMin.BaboonBirdPikminEnemy` component.

That protection was intended to block Baboon Hawk -> Pikmin targeting/bite/grab, but disabling the whole adapter also prevented the inherited `PikminEnemy.Update()` death detection and `RemoveAndDisableTriggers()` cleanup from ever running.

This explains the runtime exactly:

- Pikmin latch normally;
- Pikmin damage and kill the Hawk;
- project patch has already disabled the adapter;
- native LethalMin death/unlatch cleanup never executes;
- Pikmin stay latched on the stale AttackEnemy task;
- teardown eventually clears them.

## Vanilla + LethalMin conclusion

The exact project failure should **not be attributed to normal Vanilla + LethalMin behavior**.

LethalMin's own code contains a native death-trigger/latch-removal path, and LethalMin's 1.1.0 changelog explicitly describes Pikmin falling off enemies after attacking while latched.

A pure Vanilla + LethalMin control run has not been executed in this project, so this is not a runtime-control claim. It is a code-path conclusion: the project compatibility layer was suppressing a native lifecycle that Vanilla + LethalMin keeps enabled.

## Correction to S1.42Q interpretation

The early `IsPikminOnEnemy` return in `AttackEnemyTask.IntervaledUpdate()` is real, but it is not by itself proof of an upstream dead-target softlock.

The intended two-stage lifecycle is:

1. `PikminEnemy.Update()` sees enemy death and removes/unlatches Pikmin;
2. once no longer latched, `AttackEnemyTask.IntervaledUpdate()` can reach its existing dead-target branch and finish the task.

S1.42R tried to bridge stage 2 while the project itself had disabled stage 1.

Therefore the earlier "exact upstream root cause" classification is superseded by this runtime-backed project root cause.

## S1.42S correction

Compatibility plugin v1.3.14:

- does **not** install the S1.42R `AttackEnemyTask.IntervaledUpdate()` completion patch;
- does **not** disable `BaboonBirdPikminEnemy`;
- patches exact `BaboonBirdPikminEnemy.OnColideWithPikmin(PikminAI)` with a prevention-only prefix;
- patches exact `BaboonBirdPikminEnemy.BitePikmin(PikminAI)` with a prevention-only prefix;
- retains the common `PikminAI.GrabPikmin` Baboon-Hawk failsafe;
- leaves inherited `PikminEnemy.Update()` fully active so LethalMin owns death detection, latch removal, task completion and later corpse behavior.

No config or package change is required.
