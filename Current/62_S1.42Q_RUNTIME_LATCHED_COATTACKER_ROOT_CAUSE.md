## Exact upstream cause

Decompiled `LethalMin.Pikmin.AttackEnemyTask.IntervaledUpdate()` in 1.1.108 contains:

1. If Pikmin is attacking and still latched and `attackRoutine == null`, restart attack.
2. Otherwise:
   - if intention is not Attack **OR Pikmin is still latched**, return immediately.
   - only after that early return:
     - check null enemy;
     - path to enemy;
     - check `enemy.enemyScript.isEnemyDead`;
     - call native `pikmin.FinishTaskServerRpc()`.

Therefore a currently latched Pikmin can never reach LethalMin's existing dead-target completion branch.

That is precisely why non-killing co-attackers remain latched to a dead target indefinitely.

## Why prior fixes failed

### Proximity death cleanup

The old 4.0 m scan tried to infer which Pikmin belonged to the dead Hawk from position.

That was unnecessary and incomplete because exact target identity already exists in each `AttackEnemyTask`.

### Direct RemoveCurrentTask

This bypassed native `TaskEnd -> SetToIdle -> CallResetMethods -> Unlatch` behavior and produced invalid Work/no-task state.

### External FinishTask by death scan

Native `FinishTask` itself is correct, but selecting affected Pikmin externally was fragile.

## Exact native lifecycle

`PikminAI.FinishTaskServerRpc()`

-> `FinishTaskClientRpc()`

-> `PikminAI.FinishTask()`

-> `CurrentTask.TaskEnd(callRpc: false)`

-> `PikminAI.SetToIdle()`

-> `CallResetMethods(... Unlatch: true, RemoveTask: true ...)`

This is the same path that succeeded for hcRGph.

## S1.42R design

Patch only exact:

`LethalMin.Pikmin.AttackEnemyTask.IntervaledUpdate()`

Before upstream's latched early return:

- read this exact task's own `IsPikminOnEnemy`;
- read this exact task's own `enemy`, which resolves to `pikmin.TargetEnemy`;
- read `enemy.enemyScript.isEnemyDead`;
- only when latched **and this task's own target is dead**, call native `PikminAI.FinishTaskServerRpc()`;
- skip the broken upstream method for that tick.

No:
- enemy death hook;
- scene scan;
- radius;
- name matching;
- global Pikmin registry scan;
- direct state mutation;
- direct RemoveCurrentTask;
- custom unlatch;
- custom leader restoration.

This makes the latched branch semantically match LethalMin's already-existing unlatched dead-target branch.

## Expected result

All Pikmin attacking a dead enemy — killer and co-attackers — should reach the same native task completion lifecycle.

The fix is generic to `AttackEnemyTask`, not Baboon-Hawk-specific, because the upstream bug is generic to any still-latched Pikmin whose attack target dies.
