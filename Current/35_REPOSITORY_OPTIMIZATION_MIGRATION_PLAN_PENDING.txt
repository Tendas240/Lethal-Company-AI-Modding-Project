PURPOSE
-------

The repository is the persistent knowledge, build, evidence and handover source of truth for
a long-running Lethal Company modding project that is continued across multiple ChatGPT
sessions.

The long-term target architecture is:

"Small canonical working context + targeted retrieval from the complete knowledge/evidence base."

The migration is recommended and is expected to improve the repository substantially.
Overall assessment at the time of review: approximately 9/10 useful.

The migration must optimize for all of these goals simultaneously:

1. no relevant information loss;
2. no contradictory or ambiguous current state;
3. a much smaller and more efficient initial ChatGPT context;
4. smaller repository growth where practical without harming accessibility or evidence.

CORE RECOMMENDATION
-------------------

Perform the migration, but NOT as a blind 1:1 implementation of the original optimization
proposal.

Three important technical corrections apply:

1. Extend/consolidate the repository's existing indexing and automation rather than creating
   a second parallel index system.

2. Do not aggressively replace identical files in ProfileSources/ with pointer/symlink-like
   mechanisms merely to reduce apparent duplicate size. Git is content-addressed and already
   deduplicates identical blob contents in its object store.

3. PROJECT_STATE must explicitly distinguish the roles that matter in this project:
   - accepted gameplay baseline;
   - latest valid runtime evidence;
   - active candidate;
   - candidate build parent/base;
   - restore/configuration baselines;
   - active runtime gate;
   - next required action.

Never collapse these into a vague "latest build" concept.

GIT DUPLICATION CORRECTION
--------------------------

The audit found roughly 37 MB of logically repeated identical file contents across the
current tree.

This does NOT mean Git necessarily stores an extra 37 MB.

Git is content-addressed: identical content uses the same blob object and multiple paths can
reference that same blob.

Therefore do NOT aggressively convert ProfileSources into pointer/symlink structures merely
to reduce apparent duplicate file size.

That could:

- reduce ChatGPT accessibility;
- make reproduction harder;
- complicate build automation;
- save little or no real Git object-store space.

Use semantic indexes and diffs instead.
