## Decision

A deterministic Drains selector is technically designable by reusing the already-proven **selector-only one-postfix architecture** used by AGDIAG1.

The reusable architecture is:

> Apply exactly one postfix to `LethalLevelLoader.DungeonManager.GetValidExtendedDungeonFlows(ExtendedLevel, bool)`, ordered after the accepted S1.42AB normalizer at `Priority.Last`; on the validated real Offense server-selection path, verify that exactly one already-returned Drains wrapper exists with `DungeonName == "Drains"`, exact `DungeonFlow.name == "DrainsFlow"`, and final normalized rarity `100`; only then reduce that fresh result list to the same existing wrapper as a singleton.

This remains a **selection-only** diagnostic technique. It must not manufacture eligibility, alter rarity, registration, generation, entrance topology, NavMesh, enemies, scrap, RNG or RPC behavior.

The architecture may be reused, but **AGDIAG1 itself may not be retargeted, renamed or repurposed**. Drains requires a new separately versioned diagnostic identity and source tree if a later implementation is authorized.

This preflight authorizes no source implementation, build, publication, Gale import, activation or runtime execution.

## Why reuse is supported

Reuse is supported because the Art Gallery chain has now validated all relevant layers of the method:

1. record 253 selected the minimal one-postfix post-normalizer architecture;
2. record 255 source/static validation proved the exact LLL/normalizer dependency, patch ordering, caller validation and fail-closed local-list mutation contract;
3. the implemented AGDIAG1 patch contained exactly one intended Harmony surface and retained the same already-viable wrapper;
4. record 263 proved in runtime that this selector-only intervention could deterministically acquire the target while normal downstream DunGen generation, CullFactory materialization and PathfindingLib entrance relationships still completed;
5. no extra generation, teleport, NavMesh or observer patch was needed for the basic proof tier.

Drains has the same prerequisite shape that made Art Gallery eligible for this method:

- exact Offense classification: `VIABLE_EQUAL_100`;
- current availability mechanism: `DIRECT_LLL_UNIVERSAL_TAG_OVERRIDE`;
- no owner-hard-block bypass required;
- final normalized rarity expected to be exactly `100`;
- no Drains-specific technical warning preserved by records 245/246/264.

No new source investigation is therefore required to justify the interception **surface** itself. A later implementation still requires its own exact target literals, identity, pure tests, validator and Patch Safety Review.

- moon: exact `NumberlessPlanetName == "Offense"`;

## Minimum Drains generation/materialization proof contract

The normal-stack proof model from record 247 remains sufficient; only the target identity changes.

A future deterministic Drains run can remove Drains from the no-trusted-actual-generation-proof residual only if one coherent Offense generation contains all mandatory clauses:

### A. Deterministic target-selection provenance

- unique diagnostic `ARMED` marker, with no `REFUSED TO ARM`;
- unique selector marker proving exact Offense Drains / `DrainsFlow`, normalized rarity 100, pool `N->1`, same viable wrapper;
- no target-selection refusal marker;
- ordinary LLL/day-history or equivalent later selection context consistent with Drains.

This replaces only the old natural-selection clause. It does not weaken any downstream generation/materialization requirement.

### B. Completed generation

Mandatory:

- generation reaches `Players finished generating the new floor`;
- exact post-generation `DrainsFlow` materialization appears via CullFactory `Preparing tile information for DrainsFlow` or an equivalent exact-flow marker;
- no persistent DunGen generation-failure/retry condition prevents completion.

Useful supporting markers include:

- `Dungeon has finished generating on this client after multiple frames`;
- CullFactory `Generation has completed with seed ...`.

### C. Entrance/materialization proof

Mandatory:

- the normal generated exterior/interior PathfindingLib `EntranceTeleport` relationship set is complete and unambiguous for the concrete generated layout.

Under the current C1 proof model, the expected minimum is **four logical directional relationships** for the ordinary main/alternate pair structure. If Drains runtime topology materially differs from that assumption, the run must be classified against the concrete generated topology rather than forcing a false four-line interpretation; any such discrepancy would require bounded reconciliation before claiming PASS.

Direct player traversal remains optional for the basic generation/materialization tier. Player entry/exit would strengthen the evidence but is not required to remove Drains from this specific residual set.

### D. Negative/isolation boundaries

The run must contain:

- no persistent target-correlated generation failure;
- no invalidating diagnostic refusal after arming;
- no unexpected `[BMDSFIX1] APPLIED` on Offense.

Isolated RuntimeNavMeshBuilder or route/reachability warnings do not erase generation proof by themselves unless they correlate with a concrete failure preventing the generated layout from completing/functioning. Such signals remain separate route/NavMesh evidence.

## No extra observer patch is justified

A future Drains diagnostic does not need an `EntranceTeleport` observer or any generation hook.

The repository already proves normal-stack observability for:

- completed floor generation;
- exact CullFactory flow materialization;
- PathfindingLib entrance relationships;
- optional player facility entry/exit.

Adding observer surfaces would enlarge interception risk without solving a current observability gap.

Therefore the smallest safe design remains exactly one selection postfix.
