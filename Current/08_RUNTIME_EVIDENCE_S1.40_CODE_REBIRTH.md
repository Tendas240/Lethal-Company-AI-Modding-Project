# 08 — S1.40 Runtime Evidence: CodeRebirth Config Retention Failure

## Source set

Evidence comes from:
- user-observed S1.40 runs;
- full S1.40 `LogOutput.log` supplied in chat;
- post-run `CodeRebirth.cfg` supplied by the user after those runs.

A durable extracted config reference is stored at:

`References/Runtime-Configs/S1.40_CodeRebirth_postrun_relevant.txt`

## Run observations

The user first reported:
- a Flash Turret;
- a Wallet.

The user later suspected that the first S1.40 Gale import may have omitted:

**Advanced options -> Import all files**

That possible import mistake means the first Wallet observation alone is not sufficient to judge the intended S1.40 config.

The user then ran additional S1.40 rounds:
- no Coins/Wallets were visually found in those additional runs;
- a Flash Turret was still seen.

The later Flash Turret observation means S1.40 still failed acceptance.

## Runtime plugin validity

The S1.40 runtime log showed the cumulative local plugin marker:

`S1.39 Compatibility Fixes loaded.`

Therefore the project-local compatibility DLL was active in the analyzed runtime.

## Currency runtime evidence

Runtime logs contained instantiated CodeRebirth Currency object clones, including:
- `NewCoinPrefab(Clone)`
- `DollaBill(Clone)`
- `Wallet(Clone)`

This does not by itself prove every instance was spawned by the exact same natural map-object route, but it means "I did not visually find one" is not sufficient proof of deterministic suppression.

## Decisive post-run config evidence

The supplied post-run `CodeRebirth.cfg` was generated by CodeRebirth v1.6.9.

### General

It contained:

```ini
[General]

Clean Unusued Configs = true
```

The spelling `Unusued` is the actual CodeRebirth config key.

### Flash Turret

It contained:

```ini
[FlashTurret Options]

Enabled = true
Flash Turret | Allow Editing Config = false
Flash Turret | Is Inside Hazard = true
Flash Turret | Is Outside Hazard = false
```

This directly contradicts the intended S1.40 value:

`Flash Turret | Is Inside Hazard = false`

### Currency

Coin / Crisp Dollar Bill / Wallet had their normal positive Inside Moon Spawn Weight curves again.

The config also showed `Inside Spawn Prioritise Moon = true` for the relevant map-object definitions, so blank Interior curves alone are not sufficient if the Moon curves return to positive values.

## Conclusion

S1.40's sparse preseeded config overrides were not retained through CodeRebirth startup/config handling.

S1.40 is therefore a confirmed failed acceptance candidate.

## S1.40A hypothesis

S1.40A keeps all S1.40 suppression values and adds:

```ini
[General]

Clean Unusued Configs = false
```

Isolation goal:
- prevent CodeRebirth from removing/replacing the preseeded DawnLib entries;
- avoid changing the local compatibility DLL at the same time.

## S1.40A decision tree

After the S1.40A test:

### If config values survive and no Currency/Flash Turret naturally spawn
Accept S1.40A and proceed to S1.41 BCMER.

### If config values do not survive
Diagnose CodeRebirth/DawnLib config binding order again. Do not proceed to BCMER.

### If config values survive but Currency/Flash Turret still naturally spawn
Config is not the effective runtime authority. Stop iterating sparse config values and patch the actual DawnLib registration/spawn path directly.
