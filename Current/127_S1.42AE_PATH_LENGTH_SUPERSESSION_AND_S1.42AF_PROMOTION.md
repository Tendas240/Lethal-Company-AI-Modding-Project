# 127 — S1.42AE Path-Length Supersession and S1.42AF Promotion

**Date:** 2026-09-05  
**Status:** CURRENT LIFECYCLE DECISION  
**Accepted baseline:** S1.42AC — BCMER EventType Equal Distribution  
**Superseded candidate:** S1.42AE — Functional Microwave Provider Contract Correction  
**Active candidate:** S1.42AF — Path-Length-Safe Microwave Packaging

## Decision

S1.42AE is superseded for packaging/path-length reasons and is **not** classified as a Functional Microwave gameplay/runtime rejection. Its provider-contract code never executed during the failing launches. S1.42AF is promoted as the active runtime candidate and is built directly from accepted S1.42AC.

## Evidence that changed the lifecycle

After the v2.4 Gale importer succeeded, it derived both SoundAPI critical contracts and positively verified the nested LC binding. A direct local filesystem check immediately before launch showed `me.loaforc.soundapi.lethalcompany.dll` present at the exact runtime-consumed nested path with size `40960` bytes. The game still failed in `AutoHookGenPatcher` / `FixPluginTypesSerialization` before chainloader startup with `DirectoryNotFoundException` / `FileNotFoundException` for that same path. A second direct filesystem check immediately after the failed launch again showed the package root, nested directory and DLL present, with the DLL still `40960` bytes.

The exact S1.42AE nested binding path measured **262 characters** on the runtime host. The accepted S1.42AC control had previously passed the same SoundAPI dependency family and its corresponding nested path measured **247 characters**. The combination of physically present bytes, persistent post-failure presence, legacy BepInEx/Mono path access failure, and the 260-character boundary makes path-length compatibility the leading root-cause classification. The S1.42AF runtime test is the controlled confirmation.

## S1.42AF one-variable design

S1.42AF uses Gale profile name `LC V1 S1.42AF Microwave Fix` and profile `Profiles/LC V1 S1.42AF Microwave Fix.r2z` with SHA-256 `6a82a42bfe010767f4f39aab4d108fa45268407d9658a3e2410162cf9f6f47d0`. It was built by workflow `33993880634` / commit `2cab9044579e74739669440699c763a32f0fe379` directly from S1.42AC `0ce58ab1fa0f0d76d6fbe1a4bff1dce9defc92e3d4b70cfb3056306e617e47d9`. Automated archive QC found exactly one changed existing member (`export.r2x`) and exactly one added member (`BepInEx/plugins/S142AECodeRebirthMicrowaveSpawnTuning/S142AECodeRebirthMicrowaveSpawnTuning.dll`), with no mod/package/config drift.

The S1.42AE source project is reused unchanged. The fresh S1.42AF DLL SHA-256 is `41ae2442983d89d9b317b3930f1f53aefaa63e56bfeae0cdb198f43b0bac089f`; it is not byte-identical to the prior AE build, so binary identity is not claimed. Runtime plugin/log markers intentionally retain the `S1.42AE CodeRebirth Microwave Spawn Tuning 1.0.0` identity.

The shortened profile name is expected to reduce the previously failing nested binding path to approximately **226 characters** on the validated host.

## Runtime boundary

S1.42AF remains unaccepted until a valid run proves: v2.4 import/materialization success; shortened binding path below 260; healthy BepInEx preloader/main menu/lobby; expected unchanged plugin marker; CodeRebirth 1.6.9 and DawnLib/Dusk 0.9.25 validation; `PrioritiseMoons=true, MoonCurves=18, InteriorCurves=18`; both exact keysets; final 18 Moon/tag curves x0.5 marker with 18 Interior/tag curves validation-only; normal moon/interior generation; and no new fatal/project-critical regression.

S1.42AC remains the accepted rollback/full-normal-stack baseline. No successor after S1.42AF is armed.
