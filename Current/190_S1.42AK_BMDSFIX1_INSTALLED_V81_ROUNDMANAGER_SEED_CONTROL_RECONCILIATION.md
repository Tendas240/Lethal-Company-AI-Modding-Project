## Reconciled RoundManager findings

The exact installed V81 capture confirms the reconstructed seed path inside `RoundManager`:

1. `LoadNewLevel(int randomSeed, ...)` forwards the same value into `LoadNewLevelWait(randomSeed)`.
2. `LoadNewLevelWait` forwards the same seed into `GenerateNewLevelClientRpc(...)`.
3. `GenerateNewLevelClientRpc` assigns `playersManager.randomMapSeed = randomSeed` and initializes the RNGs before dungeon generation.
4. `InitializeRandomNumberGenerators()` sets `LevelRandom = new System.Random(playersManager.randomMapSeed)`.
5. The positive-total-weight path in `GetRandomWeightedIndex(...)` consumes one `NextDouble()` draw for the weighted choice.
6. `GenerateNewFloor()` performs that weighted dungeon-flow choice before the later `LevelRandom.Next()` used as the DunGen generator seed.

The prior 3-of-3 normal Black Mesa reconstruction therefore remains valid with the RoundManager RNG-body bridge upgraded from version-aligned public source to exact-installed binary evidence.
