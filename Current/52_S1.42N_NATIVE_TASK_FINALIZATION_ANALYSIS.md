This is the decisive control case.

## Root cause

**CONFIRMED:** `PikminAI.RemoveCurrentTask()` is a low-level task-reference cleanup and is insufficient when a Pikmin is still in LethalMin's Work/attack state.

Calling it directly leaves:
- Work state active;
- task reference null;
- follow/leader behavior unavailable;
- in at least one case, the attack-hit loop still running.

The native high-level completion path is represented by `Task finished` followed by the idle/task cleanup sequence.

## S1.42O direction

Resolve and invoke exact declared no-argument `LethalMin.PikminAI.TaskFinished()` at Hawk death instead of directly calling `RemoveCurrentTask()`.

Requirements:
- exact method only;
- validate declared type, void return, zero parameters, method body;
- if not resolvable, log candidate methods and perform no destructive low-level fallback;
- keep the S1.42N one-shot SpawnedEnemies resolver;
- keep the 4.0 m release zone;
- keep corpse protection unchanged;
- retain explicit per-Pikmin and aggregate diagnostics.

Do **not** fall back to direct `RemoveCurrentTask()` for attack-state cleanup.
