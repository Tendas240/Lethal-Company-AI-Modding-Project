## Why S1.42AF exists

Repeated S1.42AE launches failed in the BepInEx preloader before the Microwave provider patch could execute. The v2.4 Gale importer then positively proved the nested SoundAPI binding DLL was physically materialized and non-empty. A direct filesystem check immediately before launch and again after the failed launch showed the DLL still existed with size 40960 bytes.

The exact S1.42AE nested binding path was measured at 262 characters. Accepted S1.42AC previously passed the same SoundAPI dependency family with the corresponding nested path at 247 characters. The observed BepInEx/Mono failure was `DirectoryNotFoundException` / `FileNotFoundException` while opening the physically present long path.

This evidence makes a legacy Windows/Mono path-length compatibility boundary the leading root-cause hypothesis. It does not constitute an S1.42AE Microwave-logic rejection because S1.42AE's provider code never executed.

S1.42AF isolates that hypothesis by shortening only the generated Gale profile identity while rebuilding directly from accepted S1.42AC with the same functional patch source and the same package/config state.

Expected nested LC-binding path length on the validated runtime host with the S1.42AF profile name is approximately 226 characters, providing material headroom below the classic 260-character boundary.
