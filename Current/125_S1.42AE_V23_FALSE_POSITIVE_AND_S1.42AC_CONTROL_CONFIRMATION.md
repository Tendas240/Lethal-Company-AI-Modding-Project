## Third S1.42AE attempt — invalid import/materialization evidence

The same S1.42AE artifact was re-imported through `RuntimeTools/ReplaceActiveGaleProfileV23.ps1` and then launched. The game again failed in the BepInEx preloader before S1.42AE's Microwave provider-contract code could execute.

The runtime failure matched the second attempt:

- `AutoHookGenPatcher` could not read the nested LethalCompany SoundAPI binding DLL;
- `FixPluginTypesSerialization` then failed with a `System.TypeInitializationException` / inner `System.IO.FileNotFoundException`;
- BepInEx terminated in the preloader;
- S1.42AE's own runtime/provider markers were never reached.

Therefore this is **not** an S1.42AE runtime rejection.

## v2.3 proof failure identified

The PowerShell console from the v2.3 import exposed the actual proof defect before the game launch:

```text
New-Object : Cannot find an overload for "StreamReader" and the argument count: "5".
```

This came from the inherited v2.2 `Get-ZipEntryText` implementation. On the user's Windows PowerShell 5.1 environment, the five-argument `New-Object System.IO.StreamReader -ArgumentList ...` construction failed as a non-terminating error.

The next derivation then also failed because the export text was empty:

```text
Get-RequiredCriticalMaterializationPaths : Cannot bind argument to parameter 'ExpectedExportText' because it is an empty string.
```

Those errors did not terminate the importer. `$criticalMaterializationPaths` therefore resolved effectively empty, allowing the later import-completion path to print a false-positive success statement without proving either SoundAPI dependency.

This invalidates the positive v2.3 materialization message from the third attempt. It does not invalidate the exact `.r2z` profile SHA or S1.42AE build artifact itself.
