# 33 — S1.42J Baboon Hawk Zero Interaction Build

**Date:** 2026-09-03  
**Game:** Lethal Company V81

## Why S1.42J exists

S1.42H runtime evidence proved that Baboon Hawks can repeatedly grab/hold invincible Pikmin and create grabbed-death-timer + leader-null loops.

S1.42I was then built as a narrow invincible-Pikmin GrabPikmin guard, but it was **not runtime-tested**.

Before testing S1.42I, the user clarified the desired gameplay rule:

**Baboon Hawks and Pikmin should not interact at all in either direction.**

Reason:
if Pikmin are invincible, allowing Baboon Hawks to target/chase them while the actual grab is blocked creates pointless AI work and undesirable behavior.

Therefore S1.42I is superseded as an untested intermediate candidate and S1.42J implements the stronger binding rule.

## Binding Baboon Hawk rule from S1.42J onward

### Baboon Hawk -> Pikmin

No meaningful interaction:
- no Pikmin targeting/chase through the LethalMin Baboon adapter;
- no BitePikmin;
- no GrabPikmin;
- no beak hold;
- no Pikmin grabbed death timer;
- no leader removal caused by Baboon Hawk;
- no Baboon-caused leader-null loop.

### Pikmin -> Baboon Hawk

No attack/latch.

Implementation:
LethalMin `[Pikmin Behavior] Attack Blacklist` now includes the exact runtime enemy name:

`Baboon hawk`

Existing `Crawler` blacklist entry remains.

## Technical implementation

Compatibility plugin version:
**1.3.7**

S1.42J deliberately avoids any S1.42D-style broad inherited reflection/Harmony scan.

The Baboon Hawk side uses three narrow layers:

1. **Exact LethalMin adapter disable**
   - exact runtime type: `LethalMin.BaboonBirdPikminEnemy`;
   - exact vanilla spawn lifecycle anchor: declared `BaboonBirdAI.Start`;
   - one frame after Start, disable only the exact LethalMin Baboon/Pikmin adapter component;
   - no Update-driven global scene scan.

2. **Exact BitePikmin guard**
   - inspect only declared methods on exact `LethalMin.BaboonBirdPikminEnemy`;
   - directly patch only exact declared void `BitePikmin`;
   - prefix blocks the original.

3. **Common GrabPikmin failsafe**
   - retain the exact one-time patch on declared `LethalMin.PikminAI.GrabPikmin(Transform,float,int)`;
   - if the snap point belongs to Baboon Hawk/Baboon Bird, block GrabPikmin for **all Pikmin**, not only invincible Pikmin.

The adapter type's declared Pikmin-related method names are logged at startup for diagnostics only. They are not broadly patched.

## Expected runtime markers

Initialization:
`[BaboonHawkPikminGuard] Zero-interaction initialized; bitePatched=True; baboonStartPatched=True; declaredPikminMethods=[...].`

Per spawned Baboon Hawk:
`[BaboonHawkPikminGuard] Disabled LethalMin.BaboonBirdPikminEnemy on BaboonHawkEnemy(Clone). Baboon Hawk -> Pikmin targeting/chase/bite adapter is inactive.`

Failsafe markers, which should ideally not need to fire during normal zero-interaction:
`[BaboonHawkPikminGuard] Blocked LethalMin BaboonBirdPikminEnemy.BitePikmin. Baboon Hawks must ignore Pikmin completely.`

`[BaboonHawkPikminGuard] Blocked Baboon Hawk -> Pikmin GrabPikmin failsafe before hold/leader/death-timer state mutation.`
