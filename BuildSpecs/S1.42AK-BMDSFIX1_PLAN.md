# S1.42AK-BMDSFIX1 — Black Mesa x Deep Sewers Generation-Size Fix Plan

**Status:** SOURCE IMPLEMENTATION / STATIC REVIEW ONLY / NOT BUILT / NOT ARMED / NOT ACCEPTED  
**Base gameplay build:** accepted `S1.42AK` only  
**Runtime incident evidence:** `RuntimeEvidence/S1.42AK-BMGHDIAG2/20260924T124542Z/`  
**Scope:** exact pair `Black Mesa` x `DeepSewersFlow`; no universal size override

## Runtime finding that motivates this patch

The uploaded BMGHDIAG2-session log does not qualify Black Mesa x Greenhouse because BMGHDIAG2 itself failed closed at startup with `EntranceTeleport manifest module identity mismatch`. Normal behavior was preserved, so the subsequent Black Mesa dungeon choices were ordinary LethalLevelLoader selections rather than diagnostic forcing.

The first Black Mesa attempt in that session completed dungeon generation. The later attempt selected `Deep Sewers` and logged:

- `CurrentLevel: Black Mesa DungeonSize Is: 3.25 | Leaving DungeonSize As: 4.875`;
- `Final length multiplier: 4.87`;
- repeated `DunGen.NoMatchingDoorwayPlacementResult` and `DunGen.TileIsCollidingPlacementResult` failures;
- no later dungeon-generation completion before the captured log ended.

That is the evidence-backed owner path for the observed persistent `Entering the atmosphere` loading state. This patch does not claim that every historical atmosphere hang had the same cause.

## Source/owner boundary

Repository C3E3E source evidence binds accepted LethalLevelLoader `1.7.12` to release commit `f9998b91adf242cd8d735f4e697d55b32b94bfac` and establishes its generation-size path:

1. `InjectHostDungeonSizeSelection` requests the host dungeon-flow size;
2. `GetDungeonFlowSizeServerRpc` obtains `DungeonLoader.GetClampedDungeonSize()`;
3. `SetDungeonFlowSizeClientRpc` assigns that host value to `DungeonGenerator.LengthMultiplier`;
4. LethalLevelLoader then calls the normal dungeon generator.

The same exact LLL release already contains a Deep Sewers compatibility hook that repairs the first tile's automatic bounds before generation. BMDSFIX1 preserves that owner behavior and does not replace DunGen generation, retries, DawnLib ownership, LLL flow selection, entrance handling or the existing Deep Sewers tile-bounds compatibility.

C3F13/C3F14 evidence establishes `DeepSewersFlow` length `18..20` and installed DunGen semantics `targetLength = Max(RoundToInt(flowLength * LengthMultiplier), 2)`. A multiplier of `4.875` therefore requests roughly 88–98 main-path tiles before other generation constraints, matching the observed placement-failure pressure.

## Exact mutation

New plugin source: `Patches/S142AKBMDSFix1/`.

It installs exactly one Harmony postfix on public static parameterless `LethalLevelLoader.DungeonLoader.GetClampedDungeonSize()` and validates before arming:

- LethalLevelLoader plugin GUID `imabatby.lethallevelloader`;
- exact version `1.7.12`;
- exact accepted runtime DLL SHA-256 `b95aad3813dd7dc1d50aa29c9606660022b149790905a1589180e19d7c157c8c`;
- exact target method signature/body.

The pure pair policy changes the returned multiplier only when all are true:

- moon name is exactly `Black Mesa`;
- current dungeon flow is exactly `DeepSewersFlow`;
- LLL's calculated multiplier is finite and greater than `1.0`.

Then and only then the returned value becomes exactly `1.0`.

The value `1.0` is not an invented global balance value: accepted Deep Sewers LLL configuration already carries dynamic-size minimum `1`, maximum `1`, and restriction scaler `1`, while dynamic restriction itself is disabled. BMDSFIX1 applies that existing safe-size boundary only to the runtime-proven failing Black Mesa pairing.

Every non-target moon, every non-target flow, values at or below `1.0`, and invalid floating-point values are returned unchanged.

## Explicit non-goals / preserved boundaries

BMDSFIX1 must not:

- change `LethalLevelLoader.cfg` globally;
- enable Deep Sewers dynamic-size restriction on every moon;
- change S1.42AB InteriorWeightNormalization or any viability/rarity weights;
- register Black Mesa through LLL or change Dawn/native ownership;
- alter Greenhouse availability;
- modify DunGen retry/generation algorithms;
- change entrance IDs/topology, CullFactory, Shatteredrooms exclusions or Black-Mesa/Pikmin routing;
- use BMGHDIAG1 or BMGHDIAG2 as a gameplay parent.

The direct binary/profile parent remains exact accepted S1.42AK.

## Runtime validation contract

A later runtime candidate is sufficient only if evidence establishes all of the following:

1. `[BMDSFIX1] ARMED` without `[BMDSFIX1] REFUSED TO ARM`;
2. Black Mesa naturally or deliberately selects `DeepSewersFlow`;
3. `[BMDSFIX1] APPLIED Black Mesa / DeepSewersFlow multiplier=...->1` appears;
4. LLL/DunGen completes generation and `Players finished generating the new floor` appears;
5. the persistent `Entering the atmosphere` state clears and normal landed gameplay begins;
6. no persistent retry flood equivalent to the failing 4.875 run remains;
7. at least one non-target generation demonstrates no BMDSFIX1 application marker and no unintended size mutation;
8. no new severe target-attributable generation, entrance, routing or NavMesh regression appears.

Acceptance remains fail-closed until that runtime evidence exists.
