**Parent diagnostic bytes:** exact published `S1.42AK-BMDSFIX1-DIAG1`

## Problem

The published DIAG1 archive itself materializes correctly, but its local Gale profile identity is long enough that two runtime-consumed nested DLL paths reach 260 and 262 characters on the observed Windows installation root. BepInEx/Mono then fails in the preloader before DIAG1 can arm.

This is a local path-length launch blocker, not diagnostic gameplay evidence and not a BMDSFIX1 rejection.

## Exact repair surface

DIAG1PATH1 is an identity-only rewrap of the exact published DIAG1 profile.

- Base profile: `Profiles/LC V1 S1.42AK-BMDSFIX1-DIAG1 Deterministic Deep Sewers Selector.r2z`
- Base SHA-256: `31c24a3752aefe040b74c5dc2c3b7f677c17068a91f8c8e2893ace615050b78e`
- New local/profile identity: `LC V1 S1.42AK-D1P1`
- Review output: `Profiles/LC V1 S1.42AK-D1P1.r2z`

The build recipe performs no plugin build, no file injection, no package change, no config change and no mod-state change. `BuildSystem/profile_builder.py` may change only the single `profileName:` field in `export.r2x`.

## Path budget

For the observed Gale profile root on the test machine, the two startup paths that failed under the original long profile identity are 260 and 262 characters. With `LC V1 S1.42AK-D1P1`, the same paths are 215 and 217 characters, leaving at least 43 characters of margin below the classic 260-character boundary.

The short identity is intentionally terse. Descriptive provenance belongs in repository records, not in a runtime directory name that is concatenated with deeply nested package paths.
