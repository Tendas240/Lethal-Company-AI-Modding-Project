# S1.42AA Plan — Interior Weight Equalization

**Date:** 2026-09-04  
**Accepted base:** S1.42Z — Jetpack Pikmin Retune  
**Base profile:** `Profiles/LC V1 S1.42Z Jetpack Pikmin Retune.r2z`  
**Base SHA-256:** `a030d4b280b4768f6859f6fea43981004c48f31060f100322206b6016a1477e4`

## Goal

Make the effective selection weight of every eligible currently registered interior equal on vanilla and custom moons, while preserving the accepted S1.42Z gameplay/runtime state and keeping unrelated deferred scopes out of this build.

The permanent project rule remains: whenever future interior packages are added and their real generated registrations/configs are known, they must be normalized into the same equal-weight architecture before that future profile can be accepted, unless a documented technical incompatibility requires an explicit exception.

## Evidence / root cause

The accepted S1.42Z `BepInEx/config/LethalLevelLoader.cfg` already contains project-normalized configured tag weights `Vanilla:100,Custom:100` and empty manual level/mod/route overrides throughout the generated dungeon configuration. Black Mesa is intentionally native-owner configured separately and already uses `lethal_company:vanilla=+100,lethal_company:custom=+100` in `Black Mesa Team.Black Mesa Half Life Moon Interior.cfg`.

However, the global LethalLevelLoader option is still:

`Inject Dynamic Matching Weights = true`

LLL describes this switch as injecting Level/Dungeon MatchingProperties supplied by mod authors on every landing. Fresh accepted S1.42Z runtime evidence proves those author weights are still affecting the effective pool: on Offense, the viable dungeon list contains unequal weights such as LiminalHouse 300, Sub Systems 275, Abandoned Foundry 250, Shatteredrooms 75, Lead Factory 70, Spelunkers Caverns (Random) 50, Crimson Keep 35, and several 25/20 entries while many other interiors are 100.

Therefore rewriting all already-normalized per-dungeon config values is not the narrow fix. The narrow owner-level change is to stop LLL from reinjecting author MatchingProperties after the project configuration has normalized the pool.

## Native-owner / restriction handling

Black Mesa remains owned by its dedicated config and must stay at `lethal_company:vanilla=+100,lethal_company:custom=+100`; do not enable the duplicate LLL content-configuration path for Black Mesa.

Shatteredrooms' documented Experimentation/Embrion exclusion is still treated as a technical compatibility guard pending proof that it is safe to remove. S1.42AA does not intentionally patch Shatteredrooms code or an explicit exclusion entry. Runtime validation must verify that the global LLL change does not create an unsafe generation path on those moons. If the exclusion disappears and cannot be shown safe, S1.42AA is not accepted and the equalization approach must be narrowed.

Minimum validation:

1. startup/main menu and lobby succeed;
2. LethalLevelLoader loads normally;
3. at least one normal moon is generated and entered without dungeon-generation failure;
4. runtime `Viable ExtendedDungeonFlows` evidence shows the eligible pool normalized to weight 100 rather than the S1.42Z unequal author weights;
5. specifically verify formerly unequal examples such as LiminalHouse, Sub Systems, Abandoned Foundry, Shatteredrooms, Lead Factory, Spelunkers Caverns (Random), Crimson Keep, Gray Apartments and DeepcoreMines when present in the tested pool;

7. Black Mesa remains single-registered/native-owner and uses the accepted effective weight architecture;
8. no duplicate registration introduced;
9. no new dungeon generation/seeding failure;
10. normal enemies, Pikmin, BCMER and accepted S1.42Z compatibility behavior remain healthy;
11. Work/no-task = 0;
12. Leader-null = 0;
13. Fatal = 0;
