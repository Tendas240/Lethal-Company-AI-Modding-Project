## Selection semantics and mutation choice

Dusk 0.9.25 with `PrioritiseMoons=true` evaluates exact Moon first, exact Interior second, then matching Moon tags. The two tables are not combined.

The shipped Interior table contains Moon-like and tag-like keys rather than the canonical vanilla Dungeon keys, so it is validation evidence for the shipped provider contract, not the mutation target. S1.42AE therefore:

1. validates both exact tables;
2. validates all curves in both tables are non-null/non-empty;
3. logs both keysets before mutation;
4. scales only all 18 Moon/tag curves by `0.5` including values and tangents;
5. never mutates the 18 Interior curves.
