# Jetpack implementation resolution

## Requirement

Increase the base Jetpack acceleration modestly as an **always-on** behavior.

Do not reinterpret this as a purchase-gated More Ship Upgrades `Jet Fuel` buff.

## Exact runtime owner

ButteRyBalance:

- GUID: `butterystancakes.lethalcompany.butterybalance`;
- version: `0.7.0`;
- exact target owner path: its `JetpackItem.Update` prefix;
- relevant field: `JetpackItem.jetpackAcceleration`.

Accepted S1.42U config:

- `Control Scheme = V49`;
- `Warmup Period = false`.

Under that frozen configuration ButteRyBalance writes `jetpackAcceleration = 10f` for the local player on every `JetpackItem.Update` prefix. Therefore there is no narrow numeric config-only base-acceleration knob while preserving V49.

Do not switch V49 to Vanilla or Dynamic to approximate the requested change.

## Frozen target

`10f -> 12f`

This is +20% base acceleration only.

It does **not** change:

- V49 inertia/handling;
- `jetpackForceChangeSpeed`;
- `jetpackDeaccelleration`;
- maximum power/speed;
- battery;
- price.

## JetpackFixes interaction

JetpackFixes:

- GUID: `butterystancakes.lethalcompany.jetpackfixes`;
- version: `1.6.3`;
- `MidAirExplosions = Off` preserved.

JetpackFixes transpiles/observes the same `JetpackItem.Update()` but does not write `jetpackAcceleration`. Its collision/death/control fixes remain intact.

High-speed ground/collision semantics are adjacent risk because +20% acceleration can reach velocity sooner. S1.42V runtime validation must cover safe landing, hard collision, high-speed ground touch and repeated flights. The project patch does not change JetpackFixes thresholds or explosion/death logic.

## More Ship Upgrades interaction

More Ship Upgrades:

- GUID: `com.malco.lethalcompany.moreshipupgrades`;
- version: `3.14.1`.

`Jet Fuel` remains:

- `Initial Acceleration Increase = 20`;
- `Incremental Acceleration Increase = 20`.

It is purchase-gated. Its transpiler applies a percentage where the original `JetpackItem.Update()` reads `jetpackAcceleration`, so it remains a separate layer on the new 12f base. A first +20% Jet Fuel level therefore reads 12f and produces 14.4f at that use site.

`Jetpack Thrusters` remains the separate maximum-speed/power layer and is unchanged.

## Exact interception

- concrete type: `JetpackItem`;
- exact declared method: parameterless `void Update()`;
- Harmony Prefix;
- `[HarmonyAfter("butterystancakes.lethalcompany.butterybalance")]`;
- `Priority.Last`;
- local-player gate mirrors ButteRyBalance;
- mutation only when `jetpackAcceleration` is approximately `10f`;
- exact replacement `12f`;
- every non-10 value is untouched.

## Why this is the smallest safe interception

The original `JetpackItem.Update()` owns broad movement, physics, collision/death and state-transition responsibilities. The patch does not skip, replace or reverse-patch the original method.

A second IL transpiler is deliberately avoided because JetpackFixes and More Ship Upgrades already transpile this same method.

A postfix is deliberately avoided because the original frame would already have consumed 10f and ButteRyBalance would restore 10f before the next original Update.

The late prefix changes only one proven owner-written input field immediately before the original body consumes it.

## Fail-closed validation

The plugin refuses to arm unless:

- ButteRyBalance exactly 0.7.0 is loaded;
- JetpackFixes exactly 1.6.3 is loaded;
- More Ship Upgrades, when loaded, is exactly 3.14.1;
- exact declared `void JetpackItem.Update()` exists;
- ButteRyBalance owns a prefix on that target;
- JetpackFixes owns a transpiler on that target;
- More Ship Upgrades owns a transpiler there when loaded;
- post-patch verification confirms the project-local prefix.

There is no fallback method scan, broad target, alternate field owner, original-method skip or IL rewrite.

## Lifecycle/network review

The patch targets the concrete `JetpackItem.Update()` only and does not patch a base `GrabbableObject`/network lifecycle method.

No new RPC, NetworkVariable, persistent save state or host-authoritative state is introduced.

The mutation mirrors ButteRyBalance's local-player gate, so each client with the same profile adjusts its own locally controlled Jetpack path.
