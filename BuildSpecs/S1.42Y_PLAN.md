## Why S1.42Y branches from S1.42U

S1.42X proved that `jetpackAcceleration` is a valid gameplay tuning lever because the diagnostic `32f` target produced an unmistakably stronger result, but the user judged 32f far too strong. S1.42X also proved the DawnLib provider-level Air Control Unit scaling architecture, but it missed CodeRebirth's separate G.R.E.G. / Advanced Airspace Control map object.

S1.42Y therefore branches directly from the accepted S1.42U profile. It reapplies the desired cumulative configuration state and injects only the two S1.42Y project-local DLLs. V/W/X tuning DLLs remain historical evidence and must not be present in Y.

#### Probability semantics

DawnLib evaluates the AnimationCurve and then converts the result to an integer spawn amount. Therefore ×0.5 is an exact 50% curve-amplitude/spawn-weight reduction, not a guarantee that a short runtime sample will show exactly half the spawned objects.
