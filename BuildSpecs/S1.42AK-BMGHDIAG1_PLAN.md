## Purpose and immutable boundary

Obtain only the missing runtime qualification for the exact pair:

- moon: Black Mesa;
- interior: `GreenhouseFlow`.

This diagnostic is not a balanced gameplay successor and is never an accepted baseline. It must derive directly from exact accepted S1.42AK and must not alter package state, unrelated config, Black Mesa ownership, Greenhouse availability configuration, `S1.42ABInteriorWeightNormalization`, the B3 matrix, Shatteredrooms exclusions, or the separate Black-Mesa/Pikmin routing-recovery scope.

2. one read-only `EntranceTeleport.TeleportPlayer()` postfix used only to record exact player traversal/topology evidence after the targeted selection has occurred.

No other gameplay interception is part of this contract.

## Minimum observation contract

C3F16 requires practical evidence beyond selection/generation. Existing runtime logs can establish selected flow, DunGen completion/failure signals and available PathfindingLib/LethalMin routing signals, but they do not unambiguously prove which entrance IDs the local player actually traversed. Therefore one read-only player-use observer is justified.

### Exact observation target

Exact installed-V81 declared method:

`EntranceTeleport.TeleportPlayer()`

Contract:

- public instance method;
- no parameters;
- return type `void`;
- method body present;
- declaring assembly hash equals the exact installed-V81 hash above.

Use one Harmony **postfix** only. It does not skip, alter, replace or retry native teleport behavior.

The implementation may read only the exact fields/properties needed to describe the completed native operation, including:

- source `entranceId`;
- source `isEntranceToBuilding`;
- source GameObject name;
- native `exitScript` reference after the original method;
- target `entranceId`;
- target `isEntranceToBuilding`;
- target GameObject name;
- source/target transforms for diagnostic coordinates.

It must perform no field write and no manual `FindExitPoint`, teleport, RPC or position mutation.

### Observer activation

The observer is inert until `targetSelectionSucceeded == true` from the exact Black Mesa x Greenhouse selection path. It must therefore remain silent during unrelated moons/interiors before the targeted selection.

A traversal event is considered successfully observed only when the original `TeleportPlayer()` has returned with a non-null opposite-side `exitScript` whose `entranceId` equals the source ID and whose `isEntranceToBuilding` is the opposite value.

Emit:

`[BMGHDIAG1] TRAVERSED id=<0..3> sourceSide=<outside|inside> targetSide=<inside|outside> source=<name> target=<name>`

Maintain diagnostic-only coverage bits for IDs 0..3 and both directions. Emit an updated coverage marker after each successful use; do not alter gameplay based on coverage.

### One-time topology snapshot

On the first successful targeted traversal, enumerate active `EntranceTeleport` objects once and log a deterministic topology snapshot.

For IDs `0,1,2,3`, a strong runtime topology observation requires exactly:

- one active `isEntranceToBuilding=true` entry;
- one active `isEntranceToBuilding=false` entry;

for each ID, with no duplicate same-side entry for those IDs.

If satisfied, emit:

`[BMGHDIAG1] TOPOLOGY_OK ids=0,1,2,3 uniqueOppositePairs=4`

Otherwise emit:

`[BMGHDIAG1] TOPOLOGY_INCONCLUSIVE ...`

and treat the runtime evidence as insufficient. Do not modify any teleport object to repair the topology.

## Runtime proof contract retained from C3F16

A later separately armed run can qualify the exact pair only when the evidence establishes all of the following:

1. **Identity:** Black Mesa is active and `GreenhouseFlow` is selected/generated.
2. **Generation:** DunGen completes without exhausted retries/fatal generation abort.
3. **Entrance materialization:** the observer records `TOPOLOGY_OK` for unique opposite-side IDs 0..3.
4. **Player traversal:** normal main entrance entry and exit succeed.
5. **Alternate-exit practicality:** IDs 1,2,3 are each directly traversed by the player; bidirectional use should be obtained where practical and is explicitly tracked by the observer.
6. **Geometry:** the player reports no severe clipping/inaccessible required entrance geometry at the exercised endpoints; successful native teleport alone is not used to overclaim visual geometry quality.
7. **Routing/NavMesh:** no new severe/persistent target-attributable route/NavMesh failure is present; use existing PathfindingLib/LethalMin signals rather than opening the separate Black-Mesa/Pikmin repair scope.

A `REFUSED`, `TOPOLOGY_INCONCLUSIVE`, wrong selected flow, generation abort, blocked required entrance, or severe target-attributable routing failure invalidates qualification. It is evidence, not a reason to silently widen the patch.

## Patch Safety Review

### Selection target

The selection target is a static query. All LLL native matching and list construction completes before the diagnostic postfix. The returned wrappers are fresh per invocation under the already-proven LLL contract. Only the exact result instance for the real server selection call on Black Mesa is reduced to a singleton.

### Observation target

`EntranceTeleport.TeleportPlayer()` remains fully native. The diagnostic postfix observes state only after the original returns. It does not intercept the network owner, destination matching, door animation, player movement, audio, inventory handling or occlusion behavior.

### Adjacent behavior that must remain normal

- terminal simulation receives the normal full pool;
- `debugResults=false`/history paths receive the normal full pool;
- other moons receive the normal full pool;
- repeated upstream selection queries rebuild their complete normal pool;
- accepted normalization remains unchanged;
- native LLL RPC synchronization and Dawn/LLL generation remain owners;
- non-target `EntranceTeleport` operations remain byte-for-byte native aside from read-only post-call logging after targeted selection;
- no Black Mesa or Greenhouse registration/config ownership changes.

### Forbidden broader alternatives

- duplicate Black Mesa LLL registration;
- Black Mesa owner-weight rewrite;
- Greenhouse rarity inflation;
- disabling all competing interiors through multiple owner configs;
- RNG manipulation;
- RPC/network selection replacement;
- prefix/transpiler on LLL selection;
- rewriting `EntranceTeleport` IDs, pairing or player positions;
- opening Black Mesa/Pikmin routing recovery;
- modifying `S1.42ABInteriorWeightNormalization`;
- unrelated package/config/gameplay changes.
