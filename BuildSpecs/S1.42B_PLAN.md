## Purpose

Resolve the S1.42A blocking LethalModDataLib 1.2.2 initialization NRE before any unrelated S1.42 tuning.

S1.42A runtime failure:

`NullReferenceException` in
`LethalModDataLib.Features.ModDataAttributeCollector.RegisterModDataAttributes()`

The decompiled LethalModDataLib 1.2.2 bulk scanner dereferences every
`Chainloader.PluginInfos.Values[*].Instance` without a null check.

## Fix

Project-local cumulative compatibility plugin is bumped to 1.1.0.

It patches only the no-argument bulk registration method when LethalModDataLib is present.

Replacement behavior:
1. iterate `Chainloader.PluginInfos.Values`;
2. skip and log entries whose `PluginInfo.Instance` is null;
3. enumerate loadable types for valid plugin instances;
4. call LethalModDataLib's own per-type `RegisterModDataAttributes(guid, type, null, null)`;
5. return control to LethalModDataLib so its normal save/load/delete event hooks can initialize.

This does **not** disable LethalModDataLib and does not intentionally change DULL content.

Expected marker:

`[LMDLGuard] Safe ModDataAttribute scan completed:`

Expected follow-through from LethalModDataLib:

`Hooking up save, load and delete events...`

and

`ModDataHandler initialised!`
